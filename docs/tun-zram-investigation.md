## Pipeline trace and why checks missed it

1. The WIFI/NOWIFI caller workflows pass separate seed files to
   `.github/workflows/build-openwrt.yml`. NOWIFI is not generated by deleting
   packages from the WIFI seed. The trigger uses its selected ref; running
   `gemini` changes does not update the older workflow/config on `main`.
2. `Generate Variables` copies the seed and runs an early, quiet `defconfig`
   before feeds, only to obtain target/cache variables.
3. Feeds are updated and installed. `Load Custom Configuration` reloads the
   original seed, then runs `libwrt.sh`. That script patches dnsmasq's hijack
   redirect; it does not modify `.config` or prune package files.
4. The old `Download DL Packages` step ran the final `make defconfig`, then
   downloaded and compiled. There was no package assertion after resolution.
   The early expansion therefore was not the cause of lost feed selections.
5. The target profile in upstream `target/linux/qualcommax/image/ipq60xx.mk:357`
   adds only its board Wi-Fi data package. It does not remove TUN or ZRAM.
   Global `=y` selections are installed by the normal rootfs build. There is no
   downstream image surgery or later `.config` overwrite after final resolution.
6. Old publication depended only on make returning success. The old
   [workflow L198–244](https://github.com/miyukowo/libwrt-jdc-ax1800-pro/blob/ef64e59038719d72769b1a0240b574215254deef/.github/workflows/build-openwrt.yml#L198)
   neither asserted manifest contents nor checked offline APK membership. It
   moved feed APKs into target `packages/` and archived whatever existed.
   A successful make legitimately excludes unselected packages. The unrelated
   `|| true` in environment/cache cleanup did not cause these omissions.

## Upstream definitions verified locally

All references are in `/home/tvp/Projects/libwrt` at `96a0ec8`:

- `package/kernel/linux/modules/netsupport.mk:507`: `kmod-tun` maps to
  `CONFIG_TUN`, `drivers/net/tun.ko`, autoload priority 30.
- `package/kernel/linux/modules/other.mk:714`: `kmod-zram` provides zram and
  zsmalloc, autoload priority 20, and conditionally selects `kmod-lib-zstd`
  for `KERNEL_ZRAM_BACKEND_ZSTD`/`KERNEL_ZRAM_DEF_COMP_ZSTD`.
- `package/kernel/linux/modules/lib.mk:136`: ZSTD requires
  `kmod-crypto-acompress` and `kmod-lib-xxhash`; its four files include
  `crypto/zstd.ko` and `lib/zstd/zstd_{common,compress,decompress}.ko`.
- `package/system/zram-swap/Makefile:14`: selects `kmod-zram` and BusyBox swap
  features. `package/utils/busybox/Makefile:30,139` selects `BUSYBOX_DEFAULT_*`
  unless `BUSYBOX_CUSTOM=y`; testing only `BUSYBOX_CONFIG_*` would be wrong.
- `package/system/zram-swap/files/zram.init:57`: reads
  `system.@system[0].zram_comp_algo`; otherwise it tries `lzo`, independently
  of the kernel default. This was a separate initialization defect in the
  `gemini` implementation. The first-boot UCI default now explicitly sets ZSTD.
- `package/base-files/files/etc/init.d/boot:4,53` runs UCI defaults at S10,
  before S15zram. `lib/functions.sh:354` enables packaged init services during
  image construction; the new image gate verifies the resulting boot link.
- `include/kernel.mk:219`: kmods depend on the exact kernel version, ABI hash
  and release. Built-ins are recognized using `modules.builtin` at L248.
  Generic kernel defaults disable TUN/ZRAM. The unavailable old built-kernel
  config prevents independent proof of its built-in state; absent APK metadata
  alone never proves that a kernel feature is absent.
- `include/image.mk:339`: the manifest describes `root.orig`. The new gate also
  inspects the actual squashfs inside the selected sysupgrade image to catch
  per-image divergence. `scripts/json_add_image_info.py` supplies the profile
  image names/digests. `include/package-pack.mk:592` defines APK metadata.

## Changes and guarantees

| Files | Purpose |
| --- | --- |
| Both `configs/jdc-ax1800-pro-*.config` | Make ZRAM/ZSTD package requirements explicit; keep existing TUN, WireGuard, NSS and wireless policy. Dependencies already resolved correctly in `gemini`. |
| `files/etc/uci-defaults/90-zram-zstd` | Set only the ZRAM algorithm through the upstream UCI mechanism. Preserve sizing, priority and other system settings. |
| `scripts/validate-firmware.py` | Separate config, image and archive gates; standard-library Python plus build-host APK/unsquashfs tools. |
| Shared build workflow and both caller workflows | Pass explicit WIFI/NOWIFI policy; validate immediately after final defconfig and before downloads; validate built image and archive before any uploads/releases; publish provenance and logs. |
| `tests/test_firmware_validation.py`, `.github/workflows/validate-build-scripts.yml` | Run positive/negative fixtures and shell checks without compiling firmware. |
| `README.md`, this report | Explain branch selection, guarantees, remaining tests and acceptance steps. |

Configuration checks require exact target, architecture and single selected
RE-SS-01 profile, all mandatory packages at `=y`, ZSTD and effective BusyBox
swap applets, and wired NSS packages. NOWIFI rejects wireless stack selections;
WIFI retains its existing wireless support. A config fingerprint detects later
changes before publication.

Image checks select the exact profile from `profiles.json`, verify image hashes,
check its manifest and exact versioned APKs, inspect APK name/version/architecture
and exact kernel dependencies, and verify APK payload integrity. The APK tool's
read-only `verify --allow-untrusted` accommodates locally unsigned APKs;
it installs nothing and does not bypass the separate ABI/dependency assertions.
The built kernel's `.vermagic`, release and module config must match the manifest
and profile metadata. Loadable modules must exist in both build output and shipped
root; built-ins need positive `modules.builtin` evidence. TUN, ZRAM, zsmalloc,
WireGuard, ZSTD and its library dependencies are covered. The extracted root's
installed package database must equal the manifest, include boot autoload and the
zram service enable link, and contain the exact first-boot ZSTD defaults.

Archive creation collects only this target's APKs and the selected architecture's
feed APKs. Conflicting basename collisions fail. The flat `packages/*.apk` release
layout is preserved, with exact archive membership and byte comparisons. Build
outputs are copied rather than moved. A separate release directory prevents the
retained `packages/` directory from being submitted as a release asset.

These are separate guarantees: image package metadata, shipped module/service
files, and archive membership are checked separately. Actual kernel loading,
TUN ioctls and swap initialization still require a booted device.

or libc dependencies may still prevent Tailscale installation; the guarantee here
is a locally installed, ABI-compatible `kmod-tun`, not compatibility of every
future remote package.

## Post-flash acceptance (repeat after reboot)

Run after the corrected image is built and flashed by the maintainer:

```sh
uname -r
apk list --installed --manifest | grep -E '^(kernel|kmod-tun|kmod-zram|kmod-lib-zstd|zram-swap|kmod-wireguard|wireguard-tools|luci-proto-wireguard) '
modprobe tun
ls -l /dev/net/tun
test -c /dev/net/tun
/etc/init.d/zram enabled
uci -q get 'system.@system[0].zram_comp_algo'
cat /proc/swaps
grep '^/dev/zram' /proc/swaps
cat /sys/block/zram0/comp_algorithm
grep -F '[zstd]' /sys/block/zram0/comp_algorithm
if command -v zramctl >/dev/null 2>&1; then
    zramctl
else
    cat /sys/block/zram0/disksize /sys/block/zram0/mm_stat
fi
```

Expect all seven requested packages installed, a TUN character device, an enabled
zram service, active `/dev/zram0` swap, and **`[zstd]`** (brackets mark the actual
selected algorithm). If TUN is built in, modprobe may be unavailable/return an
error; accept that only with the CI log's `CONFIG_TUN=y` and matching
`modules.builtin` evidence, plus the functional check below.

When `ip` supports `tuntap`, this exercises the TUN ioctl without changing routes:

```sh
ip tuntap add dev tun-ci-check mode tun
ip link show dev tun-ci-check
ip link del dev tun-ci-check
```

If the installed BusyBox `ip` lacks `tuntap`, use `ip-full` from this same build or
verify that the Tailscale client successfully creates `tailscale0`. Do not replace
the driver or create its device node manually.

Check dependency resolution without installing anything:

```sh
apk info --depends kmod-tun
apk add --simulate tailscale
```

The solver should use the already installed custom `kmod-tun`; report any remaining
repository/dependency errors instead of forcing installation. Repeat the swap,
algorithm and TUN checks after reboot to confirm initialization persistence.
